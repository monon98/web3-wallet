# 子项目：服务端（`apps/server`，`@plugin/server`）

- **本地类型**：`src/types/*.ts`，聚合出口 **`src/types/index.ts`**（`export type * from './…'`）；当前无 `paths` 别名时自 `src` 内相对引用 `./types` 或按需对齐扩展的 `~/types` 约定。
- **栈**：Fastify、TypeScript（详见 [TECHNICAL-SOLUTION.md §4.3](./TECHNICAL-SOLUTION.md)）。
- **EVM 已实现能力（骨架）**：见技术方案 **§5.2**（**JSON-RPC 转发**、Etherscan V2、**`POST /api/v1/evm/balance-reader/query`**、**`POST /api/v1/evm/batch-sender/build`**、**`POST /api/v1/tx/broadcast`**、`GET /api/v1/evm/status`、`GET /api/v1/meta`）；**原生余额**在配置 `SERVER_RPC_URL` 时优先走 RPC（`eth_chainId` 校验链一致，失败回退 Etherscan；响应含 `source`）；**ERC-20 持仓**仍依赖 Etherscan，新增 token 缓存（新鲜 60s / stale 30min）、`ETHERSCAN_TOKEN_*` 配置与 `ETHERSCAN_API_URL` 代理入口；环境变量 **§5.4**（含 `EVM_BALANCE_READER_ADDRESSES_JSON`、`EVM_BATCH_SENDER_ADDRESSES_JSON`）。此处「转发」指 JSON-RPC 请求转发，**不是网络代理**。
- **Auth 已实现（MVP）**：`POST /api/v1/auth/challenge`（5 分钟一次性挑战）、`POST /api/v1/auth/verify`（`personal_sign` 校验后签发 24 小时 Bearer 会话）、`GET /api/v1/auth/me`、`POST /api/v1/auth/logout`；challenge / session 当前为**进程内存**，服务重启失效。challenge / verify 按 IP 限流（默认 20 次/分钟），非 `SERVER_CORS_ORIGINS` 白名单 Origin 直接 403；auth 响应 `cache-control: no-store`。不保存私钥、助记词或签名原文。生产化仍需持久化 / HttpOnly Cookie 与 CSRF（见 [BACKLOG.md](./BACKLOG.md) P4-5）。
- **交易广播已实现（MVP，EVM only）**：`POST /api/v1/tx/broadcast` 要求 Bearer 会话；校验 raw tx 的 `chainId`、签名者地址与 `SERVER_RPC_URL` 的 `eth_chainId`，再经 `eth_sendRawTransaction` 广播；不接收 / 不记录私钥或助记词。Tron / BTC 广播尚未实现。
- **统一余额查询已实现（P1）**：`POST /api/v1/balances/query` 支持 EVM / Tron / BTC 三组同时查询（每组 1–20 地址），三组并行、按链 / 按地址返回部分失败；鉴权可选（无效 Bearer 401），默认匿名 30 / 登录 120 次/分钟；结果缓存 15s、stale 保留 5min。`GET /api/v1/balances/status` 返回限额、缓存与上游配置（不含密钥）。实现见 `src/routes/balances.ts`、`src/balances/*`；集成测试 `test/balances.test.ts`。
- **配置加载**：启动时按 **cwd `.env` → 仓库根 `.env`** 顺序加载（Node `process.loadEnvFile`；已存在的进程环境变量优先；实现见 `src/loadEnv.ts`）。
- **集成测试**：`pnpm --filter @plugin/server test`（`tsx --test test/balances.test.ts test/authSecurity.test.ts`）使用 Fastify `inject` + mock `fetch`，覆盖统一查询成功 / 部分失败 / 全链不可达、非法地址、可选鉴权、余额限流、ERC-20 stale 回退、status，以及 CORS / Origin 拒绝、auth 限流与安全响应头；CI 已接入。
- **Tron 已实现能力（骨架）**：**TronGrid** 数据源（`SERVER_TRON_API_URL` / `SERVER_TRON_API_KEY` / `SERVER_TRON_MIN_INTERVAL_MS`）；`GET /api/v1/tron/status`、`GET /api/v1/tron/explorer/account`、`POST /api/v1/tron/explorer/accounts`（**串行 + 节流**，单次 ≤ 20 地址）；见技术方案 **§5.2** / **§5.4**。
- **BTC 已实现能力（骨架）**：**Esplora** 数据源（`SERVER_BTC_API_URL` / `SERVER_BTC_MIN_INTERVAL_MS`）；`GET /api/v1/btc/status`、`GET /api/v1/btc/explorer/address`、`POST /api/v1/btc/explorer/addresses`（**串行 + 节流**，单次 ≤ 20 地址，主网地址校验）；见技术方案 **§5.2** / **§5.4**。
- **多地址余额 / 代币批量查询**（链上 Multicall 与 Etherscan 差异、eth_call 与 gas 说明）：[evm-batch-balances.md](./evm-batch-balances.md)。
- **日志**：使用 Fastify `LogController` 关闭默认「incoming / completed」双条；`onResponse` 单行 access 只记录**路由模板**（不记录地址查询串）；Pino `redact` 覆盖 token / 私钥 / 助记词 / 签名 / raw tx 与 URL；默认双写控制台与运行目录下 **`logs/server.log`**（每行 JSON）；`LOG_TO_FILE` / `LOG_FILE` 见 `.env.example`。
- **安全基线（P4-2）**：CORS 白名单 `SERVER_CORS_ORIGINS`、`SERVER_TRUST_PROXY` 默认关闭、响应安全头、请求 ID 白名单校验、auth / 余额限流；详见 [security.md](./security.md)。运行时依赖审计 `pnpm audit --prod` 为 **0 漏洞**（Next 16.4.2 / Fastify 5.12.7）；构建链 devDependency 残余见该文档。
- **OpenAPI（仅开发）**：`NODE_ENV !== 'production'` 时注册 `@fastify/swagger` + `@fastify/swagger-ui`；**JSON** `GET /documentation/json`，**Swagger UI** `GET /documentation`。生产环境不暴露。本地可用 **`SERVER_SWAGGER=0`** 关闭。实现见 `apps/server/src/swagger/devSwagger.ts`。
- **产品对照**：[prd-server.md](../product/prd-server.md)；整体见 [PRODUCT-OVERVIEW.md](../product/PRODUCT-OVERVIEW.md) §A5；Tron/BTC 与后续批量能力见技术方案 §4.3、§9。
